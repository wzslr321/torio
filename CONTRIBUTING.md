# Contributing

Everything in this repository is in English: code, comments, documentation,
commit messages and ADRs.

## Before you change anything

1. Read [`AGENTS.md`](AGENTS.md). It is the governing work contract, and it wins
   over any other document. If something contradicts it, say so rather than
   guessing.
2. Read the relevant [ADR](docs/adr/README.md) and, if you are touching a command
   or the config document, the matching contract in `docs/contracts/`.
3. For anything touching the trust boundary, read
   [`docs/03-architecture.md`](docs/03-architecture.md) first — especially the
   threat model, which states what this project does **not** claim.

Torio provisions a VM, a system identity and a credential boundary. A change that
looks small can move a boundary, so a pull request that touches one is expected
to say which invariant it preserves and how a reviewer can see that.

## Branches and commits

- One behaviour change per branch.
- Commit format: `type: short description`.
- Types: `feat`, `fix`, `test`, `docs`, `refactor`, `chore`, `spike`.
- Do not mix a refactor with new functionality.

## Documentation has one source

The pages in `site/*.html` **and** the runbooks in `docs/runbooks/*.md` are
**generated** by `scripts/build_docs.py` from sources in `docs/content/`:

- `docs/content/blocks/` — shared sections, addressed by file name;
- `docs/content/pages/` — site page sources;
- `docs/content/runbooks/` — runbook sources.

Do not edit a generated file — they carry a `Generated by …` header. Change the
source and run `make docs`. Include a section used in several places with
`<!-- include: id level=N heading="…" -->` rather than copying it.

A shared block renders to HTML **and** to Markdown, so it must not link to
`*.html` — those links would be dead in a runbook. Put cross-page links in the
page source, not in a block; the build enforces this.

Mark command blocks as ` ```bash ` — only then does the build highlight comments
and strings. Use ` ```text ` for values to paste and for output that is not a
command.

`site/styles.css` and `site/docs.js` are **not** generated; edit them directly.

## Tests

Every pull request runs [`.github/workflows/ci.yml`](.github/workflows/ci.yml) on
pinned Go **1.26.5**: `make validate`, `go test ./...`, `go vet ./...`, and a
separate `go test -race ./...` job.

Locally:

```bash
make validate             # docs --check + link check + artefacts + script tests
go test ./...
go test -race ./...       # before reviewing concurrency or state changes
go vet ./...
```

Every new behaviour goes RED → GREEN → REFACTOR. A spike is the only exception,
it lives in `spikes/`, and its code is either removed or explicitly approved for a
test-first rewrite — it never graduates into `internal/` unchanged.

The end-to-end harness in `spikes/v1-e2e/` needs a real Apple Silicon Mac, a
provisioned VM, Hermes Desktop and a human. `make validate` runs only its
structural assertions, which read the driver as text and never execute it.

## Review checklist

- Does the change stay in scope?
- Does it duplicate Hermes' Kanban or dispatcher?
- Is fail-closed behaviour preserved?
- Did the agent identity gain a new capability? If so, is that capability
  explicit, enumerable and verified?
- Is any control placed in a file the agent can write? That is never a boundary.
- Do the JSON output and exit codes match the contract?
- Does a test prove enforcement, rather than configuration?
- Are credentials, tokens, raw private logs or Brain content absent from output,
  logs and test fixtures?

## Architecture changes

Add a new ADR. Never edit an accepted ADR to hide the decision it recorded — a
changed decision needs a new record that supersedes the old one.

## Security issues

Do not open a public issue for a vulnerability. See [`SECURITY.md`](SECURITY.md).
