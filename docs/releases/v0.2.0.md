# Torio v0.2.0

## Highlights

### Guest commands address the instance you selected

`TORIO_INSTANCE` selects the managed VM, and `torio vm start` and `stop` honoured
it — but every command that reached into the guest did not. The prefix those
commands are built from captured the default instance at process startup, before
the selected one was resolved.

The effect was a command that operated on two machines at once: lifecycle on the
instance you named, every probe behind it on the default, and a report printing
the name you gave over evidence gathered from a VM it never touched. `torio mcp
status` could state that a credential boundary held on an instance it had not
looked at.

If you run a single default instance, nothing you saw was wrong. If you use
`TORIO_INSTANCE`, re-read anything this told you before upgrading.

### The grant is reported, not just proven

`torio mcp status` and `torio mcp install` now report what the policy documents
grant: every service in `/etc/torio-mcp/policy.d/`, its upstream endpoint, how
many tools it allows and how many of those write, identified by the same
generation digest a running broker publishes.

Under `--json` it is a `policy` object with a `services` array ordered by name.
Nothing about a service is built into the CLI — a service is a policy document,
so a second or third provider needs no new release.

A reported write tool is a count, not a capability. The count exists because a
document that marks writes must be able to say how many it grants; no binary in
this release sends MCP traffic upstream.

### Honest partial-provisioning reports

`torio mcp install` now preserves durable `changed` and `restart_required`
state when a later provisioning or verification step fails. Human and JSON
errors report the partial effect without claiming that the dormant broker was
installed or activated.

### MCP custody is documented as a boundary, not a working integration

The operator documentation now includes `torio mcp install` and `torio mcp
status`. These commands provision and verify the dedicated `torio-mcp` guest
identity, private home, client group, and root-owned policy directory.

This release does not package or activate the broker daemon or relay. It does
not perform OAuth and does not carry upstream MCP traffic. ADR-0004 remains the
delivery boundary.

### The repository is ready to be read by strangers

Nineteen decision records became five, in English. The threat model is stated
rather than implied: prompt injection and a confused agent are in scope, an
adversarial agent explicitly is not, and `SECURITY.md` names what is known and
accepted instead of describing components this product does not have.

Roughly 330 files of run transcripts, spike results and internal plans left the
working tree. They recorded closed gates and steered no open decision. The prior
tree is readable at `git show archive/pre-oss:<path>`.

This changes no behaviour of the binary.

### Written-down evidence for what comes next

The multi-service write-window spike closed and left the tree with the rest of
the pre-open-source material; it is at `git show
archive/pre-oss:spikes/001-multi-mcp-write-window/…`. Its verdict was `PARTIAL`
and it never reached the released CLI.

What is in the tree is a throwaway harness pinning remote MCP OAuth
compatibility for the Atlassian and Linear profiles — discovery with exact
issuer binding, dynamic client registration, callback state, and token refresh
across persisted generations — against an in-process fake provider. It
implements no live flow, carries a positive live guard, and can reach no real
provider. It is its own module and is not wired into the released CLI or
packaging.

### Deterministic release archive modes

Release packaging now records the CLI as `0755` and both text files as `0644`,
regardless of the source checkout's modes. This avoids a release README that is
readable only by the account that created the archive.

## Upgrade

Download the release assets with a GitHub client that already has repository
access, then let the installer verify `SHA256SUMS`:

```bash
gh release download v0.2.0 -D /tmp/torio-rel
scripts/install.sh --version 0.2.0 --base-url file:///tmp/torio-rel
```

Confirm the installed build:

```bash
torio version
```

`torio project shell` still forwards the Mac SSH agent only for the active
operator session. The persistent Hermes service receives no forwarded agent
socket, and Torio performs no automated push, merge, tag, or release.
