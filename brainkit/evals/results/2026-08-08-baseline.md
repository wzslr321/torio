## Reading this run

This is the kit as it shipped: six skills, no map of the vault in context. It is
the number the next change is measured against, and it is worth reading in one
specific way.

**The `precision` column is not a result here.** 10/10 looks like the agent
carefully declining to open the vault when a task does not call for it. The
transcripts say otherwise: it never opened the vault at any point, in any
scenario, unless the prompt said the word "notes". Asked to write a pull request
description in a repository whose vault records the exact three headings the
house style requires, it wrote its own headings and never looked. Asked how the
guest image is pinned — a decision written down in that vault — four runs in five
answered "I don't have anything on this, not in memory and not in this repo".

So `precision` 10/10 and `linkage` 0/10 are one fact seen twice. An agent that
does not know a vault exists passes every test that asks it to leave the vault
alone, and that is not the property those tests were written to find.

**What the skills do have** is discipline once they are engaged. Where the prompt
named the vault, retrieval was targeted and honest: `retrieval-one-hop` and
`retrieval-read-budget` are 5/5, meaning the right note was found by following a
link rather than by reading the tree, and inside a read budget. The retrieval
skill is good. It is simply not consulted.

**The writing half fails outright**, and separately from all of that:
`self-update-records-correction` is 0/5 because a standing rule the user states
goes into assistant-side memory rather than the user's vault.

The run that follows this one adds the session-start vault map and changes only
that.
