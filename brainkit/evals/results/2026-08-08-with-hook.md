## Reading this run

The one thing worth taking from this run is the pair of columns, not the total.

**Reading is fixed; the fix is the map, not the skills.** With the same six
skills and the same fixture, `linkage` went 0/10 → 10/10 and `retrieval` 12/20 →
20/20. The skills were never the problem. Without a map in context the agent did
not know a vault existed: the baseline transcripts show it answering "I don't
have anything on this — not in memory, and not in this repo", having looked in
its own memory directory and the working tree and stopped. Nothing in a skill
description can fix that, because a skill is consulted by a model that has
already decided the question is not about notes.

**Precision did not pay for it.** This was the risk the `precision` family exists
to catch: buy autonomy by making the agent read private notes on every prompt.
It held at 10/10 across both runs. A shell rename and a general `git` question
still leave the vault untouched, with a map of it sitting in context. So the map
is not a nudge to search — it is the difference between choosing and not knowing.

Read the baseline's precision score with that in mind: 10/10 there was not a
result, it was the same fact as the 0/10 beside it. An agent that never opens the
vault cannot fail a test that asks it not to.

**Writing is the half that does not work.** `self-update-records-correction` is
0/5 in both runs, and the transcripts say why: told a standing rule and told not
to need telling twice, the agent writes the rule into *assistant-side memory*
under `~/.claude/projects/…/memory/`, then reports it has remembered. It has —
somewhere the user cannot read, cannot grep, and did not choose. That is the
same defect the pre-release manual pass found in `brain-capture` and fixed there,
recurring through a different door, which is precisely the argument for a
benchmark over a careful re-read.

`self-update-applies-next-session` fails for the compound version of the same
thing: 3/5 recorded the convention in the vault but the next session did not
carry it into the file it wrote, 2/5 never recorded it at all.

Neither has a skill behind it. Capture is for a thought; triage is for an inbox.
Nothing in this kit is aimed at "you have just been corrected, write it down
where it will be read again", and these two scenarios are what that gap looks
like from the outside. That is the next thing to build, and it now has a
before-number to be judged against.

**What this does not say.** Five trials per scenario, one model, one fixture, and
a `loose` run in which the operator's three personal skills were also loaded —
they are listed above. This separates working from broken. It does not separate
95% from 99%, and the `self-update` bars were deliberately set at 60% because
nobody knew what to expect from them; a bar chosen before the first measurement
is a guess wearing a number.

## retrieval-honest-miss
